# Writing Style

Default tone:

- clear, calm, and practical
- technical but not needlessly academic
- explain concepts from motivation to mechanism to example
- keep paragraphs short enough for web reading
- prefer concrete examples and tradeoffs over slogans

Article structure preference:

- start with the problem, context, or motivation
- define important concepts before comparing them
- use headings to make the article easy to scan
- use lists for steps, symptoms, methods, and tradeoffs
- use code blocks when code, commands, logs, or configuration are central to the point
- finish with a concise summary when the article is explanatory or tutorial-like

Knowledge base article conventions:

- title each post as a standalone knowledge point
- do not add visible series numbering such as `01`, `Part 1`, or `第 1 篇` unless the user explicitly requests it
- avoid labels such as `入门` when they make the article sound like a course for beginners
- make every article readable on its own rather than relying on a fixed reading order
- when prerequisite knowledge is genuinely useful, link it near the beginning as `前置阅读`
- avoid sequence-dependent wording such as `上一篇` or `下一篇` unless chronology is essential

Revision preference:

- do not change the factual meaning unless the user asks
- reduce repetition and vague wording
- make transitions smoother
- keep useful personal context
- avoid turning posts into marketing copy

Markdown conventions:

- use fenced code blocks with language labels when possible
- keep inline code wrapped in backticks
- use Hugo/PaperMod-compatible Markdown
- avoid HTML unless the existing article needs it, such as image sizing or theme-specific behavior
