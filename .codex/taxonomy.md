# Taxonomy

Use stable categories and specific tags so the archive remains easy to navigate.

Existing category examples:

- `java`
- `git`
- `front`
- `sql`
- `ops`
- `automation`
- `finance`
- `diary`

Recommended category rules:

- choose one primary category for each post
- use existing categories when they fit
- create a new category only when several future posts could reasonably belong to it
- keep category names lowercase and URL-friendly

Recommended tag rules:

- tags should describe the concrete topic, technique, framework, or series
- prefer one to four tags
- keep tags lowercase when they are English technical terms
- avoid near-duplicates such as `spring boot`, `springboot`, and `spring-boot`; choose one canonical form

Suggested canonical tags:

- `refactor`
- `clean-code`
- `spring-batch`
- `springboot`
- `system-design`
- `git`
- `javascript`
- `frontend`
- `sql`
- `automation`
- `derivatives`
- `options`
- `futures`
- `swaps`

When unsure:

- ask the user if the category affects a new series
- otherwise choose the closest existing category and add precise tags
